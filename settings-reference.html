Every setting

One precept.json with every setting Precept ships, each at the value it takes when nothing sets it. It is generated from the settings classes themselves, so it is the file this version of Precept reads — nothing on this page is written by hand.

You are not meant to copy all of it. Every key here is already its own default, so a file containing it changes nothing about a run; the shortest correct precept.json is {}. Take the handful of lines you want to change and leave the rest out, where they cost nothing and cannot go stale against a later release. Configuration covers how the file is found, overlaid and overridden; this page is the inventory.

Two things worth knowing before reading it:

  • A section is only read if the module that owns it is registered. A Web block in a project that never calls AddPreceptWeb() is read by nothing and reports nothing — see where a section comes from.
  • Every key here can also come from the environment, which is how a pipeline overrides a run and how a credential stays out of source control. Web:Headless is PRECEPT_WEB__HEADLESS; Environment variables is that list.

Comments and trailing commas are allowed in these files — .NET's JSON configuration provider skips them — so the annotations below can stay in anything you copy.

{
  // The schema this file is validated against. Read by editors, and by nothing in Precept.
  "$schema": "https://autom3tion.github.io/precept-docs/precept.schema.json",

  // Directory for run artifacts, relative to the test binary unless rooted.
  "ArtifactDirectory": "PreceptArtifacts",

  // Named database connection strings for the data module.
  "ConnectionStrings": {},

  // How many times a failing test is rerun when it has no explicit RetryAttribute. 0 — the default
  // — reruns nothing; 2 means a test may run three times in all.
  "DefaultRetries": 0,

  // Default per-test timeout in milliseconds; 0 disables the default timeout.
  "DefaultTimeoutMilliseconds": 0,

  // Name of the environment under test, used to pick the settings overlay file.
  "Environment": "local",

  // Whether this run is on a build agent. Detected from the variables the common CI systems set,
  // and overridable like any other setting — PRECEPT_ISCONTINUOUSINTEGRATION=true makes a
  // developer's run behave as a CI one for the evening, without a file to edit and revert.
  "IsContinuousIntegration": false,

  // How many units of work may be in flight at once, where a unit is whatever ParallelScope says it
  // is. Defaults to the processor count. A run cannot exceed the number of units it actually has,
  // so this is a ceiling and not a target.
  "MaxParallelism": 0,

  // Whether a class or a single test is one unit of parallel work. Defaults to the class. One of:
  // Class, Test.
  "ParallelScope": "Class",

  // HTTP API settings, bound from the Api section of precept.json.
  "Api": {
    // Base address that relative request paths are resolved against.
    "BaseUrl": null,

    // Headers sent with every request.
    "DefaultHeaders": {},

    // Attach full request and response bodies to the test log.
    "LogPayloads": true,

    // Request timeout in milliseconds.
    "TimeoutMilliseconds": 30000
  },

  // Settings for the assertion engine.
  "Assertions": {
    // How long to wait between attempts, in milliseconds.
    "PollIntervalMilliseconds": 100,

    // How long a waiting assertion keeps re-reading its value, in milliseconds.
    "TimeoutMilliseconds": 5000
  },

  // Tests that this run pretends do not exist. See PreceptFilterSettings.
  "Filter": {
    // Remove tests matching this expression, whatever Include says.
    "Exclude": null,

    // Run only tests matching this expression. Empty runs everything.
    "Include": null
  },

  // gRPC settings, bound from the Grpc section of precept.json.
  "Grpc": {
    // Default server address, for example https://localhost:5001.
    "Address": null,

    // Allow HTTP/2 without TLS. Needed for plaintext gRPC endpoints in test environments.
    "AllowInsecure": true,

    // Default deadline applied to calls that do not set one, in milliseconds.
    "DeadlineMilliseconds": 30000,

    // Record request and response messages in the test log.
    "LogMessages": true,

    // Largest response message accepted, in bytes.
    "MaxReceiveMessageSize": 4194304
  },

  // Settings for the reporting pipeline. Each reporter's own settings live in a subsection of the
  // same Reporting block and are bound separately — see PreceptReportingSettings.
  "Reporting": {
    // Overrides where every reporter runs, whatever each one says for itself: true confines the lot
    // to a build agent, false lets the lot run anywhere. Unset — the default — each reporter
    // decides, and the three shipped ones are CI-only.
    "CiOnly": null,

    // Turns the whole pipeline off. Nothing is constructed and no queue is started, which is what
    // an overlay wants when a developer's local run should not reach a shared dashboard.
    "Enabled": true,

    // How many times one reporter may throw before it is dropped for the rest of the run. A
    // destination that is down should cost one message, not one per test.
    "MaxFailures": 10,

    // How many failed tests Failures carries. Zero keeps none; Failed is the real count either way.
    "MaxTrackedFailures": 100,

    // How many events may be waiting for one reporter before further ones are dropped.
    "QueueCapacity": 4096,

    // How long the run waits, after the last test, for reporters to finish sending. Whatever is
    // still queued when it expires is abandoned and reported as abandoned.
    "ShutdownTimeoutSeconds": 60,

    // Azure DevOps reporting, bound from Reporting:AzureDevOps in precept.json.
    "AzureDevOps": {
      // REST API version the calls ask for.
      "ApiVersion": "7.1",

      // Upload each failed test's captured files as attachments of its result.
      "AttachArtifacts": true,

      // How many results are sent per call. Results are batched so that a thousand-scenario suite
      // costs about ten requests rather than a thousand.
      "BatchSize": 100,

      // Build the run is associated with, so it appears on that build's Tests tab.
      "BuildId": null,

      // File results only from a build agent, which is the default: a test run belongs to a
      // pipeline, and results a developer produced while writing a scenario are not the ones a test
      // plan should show as its latest. Set it to false — or Reporting:CiOnly, for every reporter
      // at once — to file from your own machine.
      "CiOnly": true,

      // Whether to create a test run at all.
      "Enabled": true,

      // Largest artifact uploaded, in bytes. Azure DevOps itself caps an attachment at 100 MB.
      "MaxAttachmentBytes": 8388608,

      // Report only tests that name a Test Case work item, in a TestCaseTagPrefix tag or through
      // TestCaseTitlePattern. Off by default: an unmapped test still belongs in the run, it just is
      // not linked to a work item.
      "OnlyMappedTests": false,

      // The organization, for example https://dev.azure.com/acme.
      "OrganizationUrl": null,

      // A personal access token with Test Management (read & write).
      "PersonalAccessToken": null,

      // The team project the test run belongs to.
      "Project": null,

      // Who the run and its results are attributed to — Azure DevOps shows it as Run by. Defaults
      // to whoever the token belongs to: your own account for a personal access token, and the
      // build service identity from a pipeline.
      "RunBy": null,

      // Name of the test run. Defaults to the assembly name and the environment.
      "RunName": null,

      // Tag prefix that names the Test Case work item a scenario covers: @tc:41207 files this
      // test's result against work item 41207. Set it to null or empty to read ids from the title
      // only.
      "TestCaseTagPrefix": "tc:",

      // Pattern that reads the Test Case work item out of the test's title, so a suite can carry
      // its ids where they are already visible — Scenario: [41207] A customer checks out — rather
      // than in a tag per scenario.
      "TestCaseTitlePattern": "^\\s*(?:\\[(?<id>\\d+)\\]\\s*)+",

      // Test plan the run is filed under, when the results belong to one.
      "TestPlanId": null,

      // Suite within TestPlanId whose points the results are filed against. Optional: left unset,
      // every point the plan has for a test case is filed, which is what a plan with one suite per
      // feature means.
      "TestSuiteId": null,

      // How long any single call may take, in seconds.
      "TimeoutSeconds": 60
    },

    // ReportPortal reporting, bound from Reporting:ReportPortal in precept.json.
    "ReportPortal": {
      // The API key of the account the launch is reported under.
      "ApiKey": null,

      // Upload screenshots, traces and other captured files as attachments.
      "AttachArtifacts": true,

      // Attach artifacts of passing tests too, rather than only of failures.
      "AttachOnSuccess": false,

      // Attributes put on the launch. The environment is added automatically.
      "Attributes": {},

      // Report only from a build agent, which is the default: a launch belongs to a pipeline, and a
      // developer's machine has neither the API key nor a reason to add runs to the project's
      // statistics. Set it to false — or Reporting:CiOnly, for every reporter at once — to report
      // from your own machine.
      "CiOnly": true,

      // Description shown on the launch. Defaults to a line naming the environment.
      "Description": null,

      // Whether to report to ReportPortal at all.
      "Enabled": true,

      // Base address of the ReportPortal instance, without the /api path.
      "Endpoint": null,

      // DEFAULT for a launch everyone sees, DEBUG for one kept out of the project's statistics —
      // which is what a run from a developer's machine usually wants.
      "LaunchMode": "DEFAULT",

      // Name of the launch. Defaults to the test assembly's name.
      "LaunchName": null,

      // Send the lines a test logged as log entries against its item.
      "LogMessages": true,

      // Largest artifact uploaded, in bytes. A Playwright trace of a long scenario runs to tens of
      // megabytes and is rarely what anyone opens from a dashboard.
      "MaxAttachmentBytes": 8388608,

      // The ReportPortal project the launch belongs to.
      "Project": null,

      // Report each test's category tags as attributes of its test item.
      "ReportCategoriesAsAttributes": true,

      // Report this launch as a rerun, so ReportPortal merges it into the previous one.
      "Rerun": false,

      // Name or UUID of the launch being rerun, when Rerun is set.
      "RerunOf": null,

      // How long any single call may take, in seconds.
      "TimeoutSeconds": 60
    },

    // Teams reporting, bound from Reporting:Teams in precept.json.
    "Teams": {
      // Post only from a build agent, which is the default: a channel wants to hear about the
      // pipeline's runs, not about every run a developer starts while working on a scenario. Set it
      // to false — or Reporting:CiOnly, for every reporter at once — to post from your own machine.
      "CiOnly": true,

      // Whether to post at all.
      "Enabled": true,

      // Extra rows for the card's fact list — a build number, a branch, a release. Values usually
      // come from CI through PRECEPT_REPORTING__TEAMS__FACTS__BUILD.
      "Facts": {},

      // What a screen reader says in place of ImageUrl.
      "ImageAltText": null,

      // Where ImageUrl goes. Set it to None to drop the image for one environment without losing
      // the URL from the shared file. One of: None, Thumbnail, Banner.
      "ImagePlacement": "Thumbnail",

      // An image for the card — a pipeline's status badge, a team logo, a shield for the
      // environment.
      "ImageUrl": null,

      // Add a button for every other destination this run reported to — the ReportPortal launch,
      // the Azure DevOps test run — as those reporters posted them to PreceptRunLinks.
      "LinkToOtherReports": true,

      // Longest a failure message may be on the card, in characters.
      "MaxFailureMessageLength": 300,

      // How many failed tests the card names before it just gives the remaining count. Read by
      // Detailed only — no other variant lists failures.
      "MaxFailuresListed": 10,

      // Which runs are worth a message. Defaults to all of them. One of: Always, Failure,
      // FailureOrFlaky.
      "NotifyOn": "Always",

      // Where the card's button goes. Left unset on an Azure DevOps or GitHub Actions agent, the
      // card links to the build that ran the suite — the agent knows its own address, so a test
      // project does not have to be told it.
      "RunUrl": null,

      // Label on that button. Defaults to naming the detected build — Open build 20260814.3 — and
      // to Open the run when the URL was configured or no build was found.
      "RunUrlTitle": null,

      // How long the post may take before it is given up on, in seconds.
      "TimeoutSeconds": 30,

      // Heading on the card. Defaults to the test assembly's name.
      "Title": null,

      // How the card is laid out. Defaults to Summary. One of: Summary, Compact, Detailed,
      // Pipeline.
      "Variant": "Summary",

      // The incoming webhook to post to, from the channel's Workflows connector.
      "WebhookUrl": null
    }
  },

  // Where the test data lives and how it behaves. Bound from the TestData section of precept.json,
  // like any other Precept settings class.
  "TestData": {
    // Directory the data files are read from, relative to the test binary unless rooted.
    "Directory": ".",

    // Load the {file}.{environment}.json overlay beside each file in Files.
    "EnvironmentOverlay": true,

    // Data files to load, in increasing order of precedence. Each one is optional, and each is
    // followed by its environment overlay — testdata.json then testdata.staging.json.
    "Files": ["testdata.json"],

    // How long LeaseAsync``1 waits for a pooled item to come free before giving up. Overridable per
    // pool.
    "LeaseTimeoutMilliseconds": 30000
  },

  // Browser automation settings, bound from the Web section of precept.json.
  "Web": {
    // Extra command-line arguments for the browser executable, written as one command line — a
    // Chromium flag such as --disable-dev-shm-usage on a container agent, or a proxy, language or
    // feature switch an environment needs. Split by ParseArgs.
    "Args": null,

    // How long a web-first assertion — Assert.That(locator).ToBeVisibleAsync() — retries before
    // failing, in milliseconds. Separate from TimeoutMilliseconds on purpose: an action waiting
    // half a minute for an element is patience, an assertion doing the same is a suite that takes
    // half a minute to tell you what is broken.
    "AssertionTimeoutMilliseconds": 5000,

    // Base address that relative navigations are resolved against.
    "BaseUrl": null,

    // Browser engine — chromium, firefox or webkit — or a Chromium channel the machine has
    // installed: chrome or edge, and their -beta, -dev and -canary variants.
    "Browser": "chromium",

    // Connect to a running Chromium over the DevTools protocol — http://localhost:9222. For driving
    // a browser that is already open, which is what a debugging session or a desktop application
    // embedding Chromium offers.
    "CdpEndpoint": null,

    // The release channel to launch instead of Playwright's own build — chrome, msedge, or one of
    // their -beta, -dev and -canary variants.
    "Channel": null,

    // The colour scheme the page's media queries see: light, dark or no-preference. Unset leaves
    // Playwright's default, which is light.
    "ColorScheme": null,

    // How much of what the page writes to the browser console is copied into the test's log. Errors
    // by default. One of: None, Errors, All.
    "ConsoleLogging": "Errors",

    // A device from Playwright's registry to emulate — iPhone 15, Pixel 7, iPad Mini landscape.
    // Sets the viewport, user agent, device scale factor and the touch and mobile flags together,
    // which is what makes a page serve its mobile layout.
    "Device": null,

    // Fail a test whose page wrote an error to the browser console, however well the assertions
    // went.
    "FailOnConsoleErrors": false,

    // Fail a test whose page threw an exception nothing caught, however well the assertions went.
    "FailOnPageErrors": false,

    // The position the browser reports, as LATITUDE,LONGITUDE — 51.5074,-0.1278.
    "Geolocation": null,

    // Record the session's network traffic as a HAR file; attached to the test when it fails.
    "HarOnFailure": false,

    // Run without a visible browser window.
    "Headless": true,

    // Continue to a site whose certificate does not validate. Off by default, and worth leaving off
    // where the certificate is real.
    "IgnoreHttpsErrors": false,

    // Whether a browser Playwright has not downloaded is installed rather than failing the run.
    // Auto by default. One of: Auto, Never, Always.
    "InstallBrowsers": "Auto",

    // The locale the browser reports, as a BCP 47 tag — en-GB, de-DE. Decides the Accept-Language
    // header and the formatting of dates and numbers the page renders.
    "Locale": null,

    // Browser permissions granted to every context up front, separated by spaces or commas —
    // geolocation, clipboard-read, notifications.
    "Permissions": null,

    // The viewport as one value: a named resolution — 720p, 900p, 1080p, 1440p, 2160p, or the
    // aliases hd, fhd, qhd, uhd and 4k — or an explicit WIDTHxHEIGHT such as 1366x768.
    // Case-insensitive.
    "Resolution": null,

    // Save a file the page downloads into the test's artifacts. On by default, and free for a test
    // that never downloads anything.
    "SaveDownloads": true,

    // Capture a screenshot when a test fails.
    "ScreenshotOnFailure": true,

    // Slow each Playwright operation down by this many milliseconds, for debugging.
    "SlowMoMilliseconds": 0,

    // A file of cookies and local storage — Playwright's storageState — that every context starts
    // from, so a suite does not sign in once per test.
    "StorageState": null,

    // Default timeout for element and navigation waits, in milliseconds.
    "TimeoutMilliseconds": 30000,

    // The time zone the browser reports, as an IANA name — Europe/London, America/New_York. Unset
    // leaves the machine's, with the same drift Locale describes and rather more of it around
    // midnight.
    "TimezoneId": null,

    // Record a Playwright trace; attached to the test when it fails.
    "TraceOnFailure": true,

    // The user agent every page reports. Unset leaves the browser's own — and a Device's, which is
    // part of what makes the emulation convincing.
    "UserAgent": null,

    // Record a video of each test; attached when it fails.
    "VideoOnFailure": false,

    // Viewport height in pixels. Ignored when Resolution names one.
    "ViewportHeight": 800,

    // Viewport width in pixels. Ignored when Resolution names one.
    "ViewportWidth": 1280,

    // Connect to a browser already running somewhere else, over Playwright's own protocol —
    // ws://grid.internal:3000/. A browser grid, or a vendor's cloud, addresses the suite this way.
    "WsEndpoint": null,

    // Credentials for HTTP basic authentication, sent to every request the context makes.
    "HttpCredentials": {
      // Restrict the credentials to this origin, scheme and port included —
      // https://staging.example.com. Unset sends them wherever the page goes, including to a
      // third-party host it happens to load an asset from.
      "Origin": null,

      // The password. Belongs in an environment variable rather than in a settings file.
      "Password": null,

      // The user name.
      "Username": null
    },

    // The proxy every browser connection goes through — the corporate proxy an agent sits behind,
    // or a recording proxy a suite runs against.
    "Proxy": {
      // Hosts to reach directly, comma-separated — localhost,*.internal. Normally where a container
      // or a local stub goes, since a proxy cannot route to the agent's own loopback.
      "Bypass": null,

      // Password, where the proxy authenticates.
      "Password": null,

      // The proxy, as http://host:port or socks5://host:port. Nothing else here means anything
      // without it.
      "Server": null,

      // User name, where the proxy authenticates.
      "Username": null
    }
  }
}

Sections of your own go in the same file and are bound the same way, and nothing above reserves a name — see your own settings. The JSON schema describes everything on this page to an editor, so most of it can be discovered by typing rather than by reading.
