Release notes

Every release of Precept, newest first. An entry lists what reaches a suite — features, fixes, performance and anything that breaks. Documentation, build and test changes are left out.

The version number says how much a release moves. A fix bumps the patch and a feature bumps the minor. While the major version is still 0, a rename or a removal bumps the minor as well, so a minor release is not always a drop-in replacement.

Before moving a suite, read every entry between the version it references and the version you are moving to, then work through Upgrading. The entries say which areas moved. The build, the schema and the settings reference say exactly what.

This page is generated from the repository's changelog, so it names the pull request titles that went into each release rather than prose written afterwards.

0.1.0#

The first release. Written by hand, because there is no earlier release to describe the difference from; every entry after this one is generated.

Precept is a .NET 10 test automation framework built directly on Microsoft.Testing.Platform, with Gherkin authoring through a Reqnroll generator plugin.

Packages#

  • Precept.TestPlatform — the runner. Discovery, parallel scheduling by declaring class, retry, timeouts, per-test DI scopes, TRX and Azure DevOps reporting. A test project starts here and needs no Main and no OutputType.
  • Precept.Core — attributes, PreceptTestContext, settings and environment overlays, outcome exceptions, and the assertion engine: await Assert.That(x).ToBeSomethingAsync(y), with .Not, .Within, .Because, Assert.Eventually and Assert.MultipleAsync supplied once by the runner so a new assertion is a single extension method.
  • Precept.Reqnroll — .feature files compile to Precept test classes, with "Go to test" landing in the feature file rather than the code-behind.
  • Precept.Api — a fluent HTTP client and response assertions, logged into the test report.
  • Precept.Web — Playwright browser automation isolated per scenario, with screenshot, trace and video capture on failure.
  • Precept.Data — provider-agnostic ADO.NET access for seeding and asserting.
  • Precept.TestData — environment-specific data sets, dynamic values, factories that clean up after themselves, and pooled records leased to one test at a time.
  • Precept.Grpc — pooled channels, typed clients, and assertions over status codes, deadlines and streaming.
  • Precept.Containers — Docker-backed dependencies for a run, via Testcontainers.
  • Precept.Templates — dotnet new precept-web and dotnet new precept-web-reqnroll.

Every package carries Source Link and ships .snupkg symbols.
